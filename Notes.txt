Facebook-style UI (blue theme, animated metric cards, auto-refresh 30s)

EC2 instances: t3.micro x2 (t2.micro wasn't free-tier eligible for us,
used t3.micro instead - same idea)
  Backend-Server-1 -> Private-Subnet-1
  Backend-Server-2 -> Private-Subnet-2
(these were later terminated in favor of ASG-managed instances)

Target Group: Backend-TG, HTTP:3000, health check path "/"

ALB: Facebook-ALB, internet-facing, listens on :80, forwards to Backend-TG
  DNS: Facebook-ALB-1354433057.us-east-1.elb.amazonaws.com

Launch Template: Backend-Launch-Template (v1 = plain UI, v2 = FB-style UI)

Auto Scaling Group: Backend-ASG
  min=1 desired=2 max=4
  target tracking: avg CPU 50%

GOTCHA: after creating ASG we ended up with 4 running instances (2 manual
+ 2 from ASG) - terminated the manually-launched ones and let ASG own
everything going forward.

--- PHASE 4: SECURITY ---
Security Groups:
  ALB-SG      : in 80,443 from 0.0.0.0/0
  Backend-SG  : in 3000 from ALB-SG only, 22 from my IP only
  Database-SG : in 3306 from Backend-SG only (reserved, no DB deployed)

NACLs:
  Public-NACL  : allow 80,443,1024-65535 in/out -> assoc public subnets
  Private-NACL : allow 3000 from public subnets, 22 from public subnet,
                 1024-65535 return traffic -> assoc private subnets
  (default VPC NACL still exists too, not deleted, just unused)

VPC Flow Logs: FacebookVPC-FlowLogs -> CloudWatch Logs group
  /aws/vpc/flowlogs
  IAM role used: auto-generated VPCFlowLogs-Cloudwatch-<timestamp>
  (the manually-created VPC-FlowLogs-Role wasn't showing up in the
  dropdown right away - used the auto-generated one instead, works fine)

Verified: direct access to private instance IP:3000 times out (correct -
proves private subnet isolation is working)
